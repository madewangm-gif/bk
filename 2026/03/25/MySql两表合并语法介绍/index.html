MySql两表合并语法介绍

原始sql：

这段 SQL 的核心是合并两张表的数据，最终返回一个包含两列的结果集，具体如下：

1. 结果集的结构

最终返回的结果只有两列：

  • id：来自 tender_project 或 tp_purchase_gov 表的 id 字段
  • insert_time：对应 id 记录的插入时间（来自同一张表的 insert_time 字段）

2. 数据来源与合并规则

  • 首先执行子查询中的

    • 第一步：从 tender_project 表中取出所有行的 id 和 insert_time
    • 第二步：从 tp_purchase_gov 表中取出所有行的 id 和 insert_time
    • 第三步：用 UNION ALL 将这两部分数据完整合并（包括重复数据，且不排序）

  • 外层查询只是将子查询的结果直接输出（相当于 “透传”，没有额外过滤 / 加工）

3. 关键特性（新手易混淆点）

  • UNION ALL 不会去重：如果两张表中有相同的 id + insert_time 组合，结果集中会同时保留，这是和 UNION（会自动去重）的核心区别。
  • 结果集的顺序：默认是先显示 tender_project 的所有数据，再显示 tp_purchase_gov 的所有数据（数据库底层存储顺序可能影响最终顺序，如需固定顺序需加 ORDER BY）。
  • 无过滤条件：会返回两张表的全部行（只要表中有数据），没有 WHERE 条件限制。

示例（直观理解）

假设：

  • tender_project 表数据：

    表格

    id insert_time
    101 2026-03-20 10:00:00
    102 2026-03-21 11:00:00

  • tp_purchase_gov 表数据：

    表格

    id insert_time
    201 2026-03-20 14:00:00
    101 2026-03-20 10:00:00 （和第一张表的 101 重复）

执行这段 SQL 后的结果：

表格

id insert_time
101 2026-03-20 10:00:00 （来自 tender_project）
102 2026-03-21 11:00:00 （来自 tender_project）
201 2026-03-20 14:00:00 （来自 tp_purchase_gov）
101 2026-03-20 10:00:00 （来自 tp_purchase_gov，重复保留）

总结

  1. 最终结果是合并 tender_project 和 tp_purchase_gov 两张表的 id、insert_time 字段，返回所有行（包括重复数据）。
  2. 结果集仅包含 id 和 insert_time 两列，无任何过滤、去重或排序。
  3. UNION ALL 是核心，保证了数据完整合并且效率高于 UNION（无需去重）。

如果需要去重，可将 UNION ALL 改为 UNION；如果需要排序，可在最后加 ORDER BY tp.insert_time。
